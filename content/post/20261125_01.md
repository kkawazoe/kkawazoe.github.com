Claude Code に組み込まれている `/code-review` スキルの使い方と、似たコマンドとの使い分けを備忘録として残しておく

本記事の内容は、以下のいずれかで裏付けが取れたものだけを記載している

- 公式ドキュメント (`code.claude.com/docs`)
- 公式 CHANGELOG (`anthropics/claude-code` リポジトリ)
- 手元の環境で実際に確認した結果 (「手元で確認」と明記)

※ Claude Code は更新頻度が高く、`/code-review` の挙動も短期間で何度も変わっている  
最新の挙動は [参考](#参考) の公式ドキュメントを確認すること

## 環境

- OS: macOS
- Claude Code: 2.1.332 (`claude --version` で確認)

## 概要

`/code-review` は Claude Code のプロンプトで実行する **バンドルスキル** で、作業中のブランチの変更を読んで **正しさに関するバグ (correctness bugs)** を探し、結果を会話に返してくれる

- どのプランでも利用でき、通常のセッションと同じく利用量 (または API 課金) としてカウントされる
- `/review` は `/code-review` のエイリアス (2.1.223 から)
- 組み込みのスキルなので、ディスク上に編集可能な `SKILL.md` は存在しない
- プロジェクト固有のレビュールールを与えたい場合は `CLAUDE.md` に書く (レビューは `CLAUDE.md` に従う)

## 基本的な使い方

### 書式

公式のコマンドリファレンスでは以下の書式になっている

```text
/code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]
```

「effort レベル → フラグ → レビュー対象」の順で指定する

### 実行の流れ

1. `/code-review` を実行する

    ```text
    /code-review
    ```

2. そのまま作業を続ける  
    ターミナルのセッションでは、レビューは独自のコンテキストを持つ **バックグラウンドのサブエージェント** として動くため、会話のコンテキストを圧迫しない (2.1.218 から)

3. 指摘が会話に届いたら、Claude に修正を依頼する

### レビュー対象の指定

対象を指定しない場合は **現在のブランチの変更 + 未コミットの変更** がレビュー対象になる

| レビューしたいもの | 入力 |
| :--- | :--- |
| 現在のブランチと未コミットの変更 | `/code-review` |
| 直近 15 コミット | `/code-review HEAD~15..HEAD` |
| ブランチ同士の比較 | `/code-review main...my-feature` |
| 単一コミット | `/code-review abc1234^..abc1234` |
| Pull Request (番号指定) | `/code-review 1234` |
| ファイル / ディレクトリ | `/code-review src/auth` |

※ 対象を省略したときの比較元は、ドキュメントでは「upstream より先行しているコミット + 未コミットの変更 (upstream がなければ `main` か直前のコミットと比較)」となっている  
一方、CHANGELOG 2.1.329 には以下の変更がある

> Changed `/code-review` with no target on most models to review the whole branch against the default branch, and fixed it losing the diff on multi-commit branches

多くのモデルでは「デフォルトブランチに対するブランチ全体」が対象になると考えてよさそう

### effort レベル

effort レベルは **網羅性と確度のトレードオフ** を指定するもの

- `low`: 最も確信度の高い指摘だけを報告する (誤検知が少ない)
- `medium` 〜 `max`: レベルを上げるほど網羅性が広がる
- `ultra`: ローカルではなくクラウドでの詳細レビュー (後述)

`high` / `xhigh` / `max` それぞれの細かな違いは、公式ドキュメントには記載がない

#### レベルを省略したとき

レベルを省略すると、**前回入力した `low`〜`max` のレベルが再利用される** (別セッションでも有効 / 2.1.223 から)  
その際は `Reusing high effort, the level you typed last time` のような通知が表示される

- レベルを入力すると、それ以降の再利用対象が変わる
- `-p` (非対話モード) で指定したレベルは記憶されない
- `ultra` は記憶されたレベルを使わず、上書きもしない
- 一度もレベルを入力したことがなければ、セッションの effort が使われる

### フラグ

| フラグ | 内容 |
| :--- | :--- |
| `--fix` | レビュー後に指摘内容を作業ツリーへ適用する (編集は permission mode に従う) |
| `--comment` | 指摘を GitHub PR のインラインコメントとして投稿する (GitLab の MR には v2.1.257 以降で `glab` 経由で 1 件のノートとして投稿) |
| `--max-findings <n>` / `all` / `default` | 報告件数の上限を変更する (通常の上限は 32 件 / 値は次回以降も再利用され、`default` で元に戻る / v2.1.288 以降) |
| `--post` | `ultra` で github.com の PR を対象にしたとき、結果を PR に投稿する選択肢をあらかじめ選んだ状態にする (v2.1.227 以降) |

`--fix` を付けない場合、レビューは **レポートのみ** を行う

#### --fix 使用時の注意

バックグラウンドで動くレビューの `--fix` による編集は、セッションのチェックポイントの外で行われる  
そのため `/rewind` では元に戻らないファイルがあり、**git で戻す必要がある**

### 何を指摘するか (最近の変更)

指摘の範囲はモデルと effort によって変わる  
CHANGELOG を追うと以下の変更が入っている

- 2.1.328

    > Changed `/code-review` on most models to report only bugs and CLAUDE.md violations; run `/simplify` for reuse, simplification and efficiency cleanups
    >
    > Changed `/code-review` to mark each finding Important, Pre-existing or Nit on most models, and to end each summary with a suggested fix; a clean review's list now reads "Code review found no issues."

- 2.1.290

    > Changed `/code-review` at medium effort to also report cleanup and CLAUDE.md conventions findings on models without tuned review settings, including Opus 5.5 and Sonnet 5.5

まとめると、**多くのモデルではバグと CLAUDE.md 違反のみ** を指摘する  
リファクタリング系の指摘 (再利用・簡素化・効率化) が欲しい場合は `/simplify` を使う

## /code-review ultra (ultrareview)

`/code-review ultra` は、Anthropic のクラウドサンドボックス上で **複数のレビュアーエージェント** を走らせる詳細レビュー  
報告される指摘は、それぞれ独立に再現・検証されたものになる

- 研究プレビュー機能で、機能・価格・提供範囲は変わる可能性がある
- `/ultrareview` はエイリアス (推奨は `/code-review ultra`)

### 前提条件

- claude.ai アカウントでのログインが必要 (API キーのみの場合は `/login` する)
- Amazon Bedrock / Google Cloud / Microsoft Foundry 経由、Zero Data Retention や HIPAA 構成の組織では使えない (その場合はローカルレビューになる)
- PR を対象にするには github.com 上のリポジトリが必要
- ブランチレビューはデフォルトで「変更ファイル 500 / 変更行 8,000」まで

### 料金

| プラン | 無料枠 | 無料枠のあと |
| :--- | :--- | :--- |
| Pro / Max / Ultra | 3 回 | 利用クレジットで課金 |

- 無料枠はアカウントごとに 1 回限りで、補充されない
- 無料枠のあとは、変更量に応じて 1 回あたり **おおむね $5〜$25**
- クラウドセッションが始まった時点でカウントされる (途中で止めても無料枠を 1 回消費する)

起動前に、レビュー範囲・残りの無料回数・見積額が確認ダイアログに表示される

### 使い方

```text
# 現在のブランチをデフォルトブランチと比較
/code-review ultra

# 比較元のブランチを変更
/code-review ultra develop

# PR を対象にする
/code-review ultra 1234

# 結果を受け取ったあと、指摘を作業ツリーに適用
/code-review ultra --fix
```

所要時間は 5〜15 分ほどで、バックグラウンドで実行される (`/tasks` から確認・停止できる)

### スクリプト / CI から実行する

`claude -p '/code-review ultra'` では結果を受け取れないため、スクリプトからは `claude ultrareview` サブコマンドを使う

手元で `claude ultrareview --help` を実行すると、以下のオプションが表示された

```text
Usage: claude ultrareview [target] [options]

Run a cloud-hosted multi-agent code review of the current branch (or a PR number
/ base branch) and print the findings

Options:
  -h, --help           Display help for command
  --json               Print the raw bugs.json payload instead of formatted
                       findings
  --no-post            Don't post the findings to the PR (the default)
  --post               Post the finished review's findings to the PR as you (PR
                       targets only; one plain comment, not a review)
  --timeout <minutes>  Maximum minutes to wait for the review to finish
                       (default: 45)
  --trust-workspace    Trust the current folder for this run only, without
                       asking (for scripts and CI). Takes no value: put a PR
                       number or base branch before it. Use it only on folders
                       you trust: the folder's git configuration and Claude Code
                       project settings can run programs
```

## 似ているコマンド / 機能

### /simplify

- 変更されたコードの **クリーンアップ** を探して、修正まで適用する
- 4 つのレビューエージェントが並列で動き、既存ヘルパーの再利用・簡素化・効率化・抽象度の妥当性を確認する
- **バグは探さない** (バグを探すなら `/code-review`)

※ v2.1.147 より前は、現在の `/code-review` が `/simplify` という名前だった  
昔のスクリプトで `/simplify` をバグ探しに使っていた場合は `/code-review --fix` に置き換える

### /security-review

- 現在のブランチの差分を、`origin` のデフォルトブランチと比べて **セキュリティ脆弱性** の観点で分析する
- インジェクション、認証の問題、データ漏えいなどのリスクを洗い出す
- `origin` リモートが必要

### Code Review (GitHub のマネージドサービス)

`/code-review` とは別物で、GitHub の PR を組織単位で自動レビューするサービス

- Team / Enterprise プランで、組織の Owner が有効化する
- PR 作成時・push ごと・リクエスト時のいずれかでレビューが走り、PR に `@claude review` とコメントしても開始できる
- レビューの深さは `Quick` / `Standard` (デフォルト) / `Deep` の 3 段階  
  ※ `/code-review` の effort レベル (`low`〜`max`) とは別の設定
- レビュールールは `REVIEW.md` で設定する (ローカルの `/code-review` は `REVIEW.md` を読まない)

## 使い分け

公式ドキュメントの比較表をもとに整理すると以下のようになる

| やりたいこと | 使うもの | 実行場所 | コスト |
| :--- | :--- | :--- | :--- |
| 開発中にさっとバグを見つけたい | `/code-review` (`low`〜`medium`) | 自分のセッション | 通常の利用量 |
| マージ前にしっかりバグを見たい (手元で) | `/code-review high` 以上 | 自分のセッション | 通常の利用量 |
| 大きな変更をマージ前に深く検証したい | `/code-review ultra` | クラウド | 無料枠 3 回、以降 $5〜$25 / 回 |
| 指摘をそのまま直してほしい | `/code-review --fix` | 自分のセッション | 通常の利用量 |
| PR にインラインコメントで残したい | `/code-review <PR番号> --comment` | 自分のセッション | 通常の利用量 |
| リファクタリング観点で整理したい | `/simplify` | 自分のセッション | 通常の利用量 |
| セキュリティ観点で確認したい | `/security-review` | 自分のセッション | 通常の利用量 |
| チームの全 PR を自動でレビューしたい | Code Review (マネージド) | Anthropic のインフラ | Team / Enterprise |

自分の運用としては以下の流れがよさそう

1. 実装中は `/code-review` (デフォルトのレベル) で素早く確認する
2. 気になる点を直したら `/simplify` でコードを整える
3. 認証・入力値を扱う変更なら `/security-review` も実行する
4. 影響範囲の大きい変更は、マージ前に `/code-review ultra` で検証する

## 補足: Claude に自動で実行させたくない場合

自然言語で「変更をレビューして」と頼むと、Claude が自分で `/code-review` を起動することがある  
自分で入力したときだけ動かしたい場合は、`~/.claude/settings.json` などに以下を追加する

```json:settings.json
{
  "skillOverrides": {
    "code-review": "user-invocable-only"
  }
}
```
